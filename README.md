## Admin–User Chat Feature
This project now includes a minimal admin–user chat in the admin panel.

- From the messages list (/), each message with a Telegram Chat ID has a link "Открыть чат".
- The chat page is available at /chat/[chatId]. It shows:
  - Incoming user messages from the `public.messages` table.
  - Admin replies from a new `public.bot_outbox` table.
- Admin can type and send replies; a new row is inserted into `public.bot_outbox` with status `pending`.
- Realtime updates are enabled: new incoming messages and new outbox rows appear automatically if Supabase Realtime is enabled for those tables.

### Required database setup (Supabase)
Create the outbox table for admin replies and set RLS policies. Run this SQL in Supabase SQL editor:

```sql
-- 1) Outbox for admin messages to users (processed by your bot/worker)
create table if not exists public.bot_outbox (
  id bigint generated by default as identity primary key,
  telegram_chat_id bigint not null,
  text text not null,
  admin_uid uuid, -- optional: who sent from admin side
  status text not null default 'pending', -- pending | sent | error
  created_at timestamptz not null default now(),
  sent_at timestamptz null,
  error_message text null
);

-- 2) Enable RLS
alter table public.bot_outbox enable row level security;

-- 3) Policies (minimum: allow authenticated admins to read/insert)
create policy if not exists "outbox select for authenticated"
  on public.bot_outbox for select
  to authenticated
  using (true);

create policy if not exists "outbox insert for authenticated"
  on public.bot_outbox for insert
  to authenticated
  with check (true);

-- (Optional) allow updates to mark status by a server role/worker only.
-- If you run a server-side worker using the Service Role key, you can keep RLS and write a policy for role 'service_role'.
-- Alternatively, disable RLS for updates and restrict via PostgREST settings. Recommended is to keep RLS and add:
-- create policy "outbox update by service_role" on public.bot_outbox for update to service_role using (true) with check (true);

-- 4) Realtime (optional but recommended)
-- In Supabase Dashboard → Realtime, enable database realtime for the schema/table `public.messages` and `public.bot_outbox`.
```

If you want to restrict chat access to specific admins only, replace `using (true)` in the policies with a check on `auth.jwt()->>'email' in ('admin1@example.com', ...)` or on a dedicated `admins` table.

### Bot/worker integration
The admin panel only inserts outgoing messages into `public.bot_outbox`. Your Telegram bot or background worker should:
- Poll or listen for `bot_outbox` rows with `status = 'pending'`.
- Deliver `text` to `telegram_chat_id` via Telegram Bot API.
- Update the row: set `status = 'sent'` and `sent_at = now()` (or `status = 'error'` and `error_message`).

Example pseudo-logic:
```ts
// Pseudo-code; run on server with Service Role key
const { data: pending } = await supabase
  .from('bot_outbox')
  .select('*')
  .eq('status', 'pending')
  .order('created_at', { ascending: true })
  .limit(100)

for (const item of pending ?? []) {
  try {
    await telegram.sendMessage(item.telegram_chat_id, item.text)
    await supabase.from('bot_outbox').update({ status: 'sent', sent_at: new Date().toISOString() }).eq('id', item.id)
  } catch (e) {
    await supabase.from('bot_outbox').update({ status: 'error', error_message: String(e) }).eq('id', item.id)
  }
}
```

### Frontend code overview
- app/page.tsx: lists messages and links to chat pages.
- app/chat/[chatId]/page.tsx: server component that checks auth and renders the client chat.
- app/chat/[chatId]/Chat.tsx: client chat component that
  - loads and merges messages from `messages` and `bot_outbox`,
  - subscribes to realtime inserts,
  - allows sending admin messages (insert into `bot_outbox`).

Notes:
- Ensure env variables `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` are correctly set in your environment (Vercel/locally).
- Realtime requires enabling the tables in Supabase → Realtime settings.
